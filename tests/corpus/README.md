# 외부 회귀 코퍼스

## 왜 있는가

이 프로젝트가 반복해서 겪은 실패가 **"자기 코퍼스에서만 측정"** 입니다.
자체 벤치마크는 100%인데 남의 코드에 겨누면 오탐이 쏟아졌습니다(라운드 10:
87.5% · 라운드 13: 차단 오탐 93.5%).

그리고 더 나쁜 것은 **고친 오탐이 조용히 돌아온다**는 점입니다. 룰을 넓히는
수정 한 번이면 재발하는데, 자체 코퍼스에는 그 형태가 없으니 초록불이 유지됩니다.

그래서 **판정이 실제로 뒤집힌 자리**를 출처와 함께 박제합니다.

## 무엇이 들어 있나

`external_regression.json` — 라운드 14에서 판정이 바뀐 실제 코드 10건.

| 필드 | 뜻 |
|---|---|
| `origin` | 저장소·커밋·경로·줄 — **검증 가능한 출처**. 언제든 원본과 대조할 수 있어야 한다 |
| `code` | 그 자리의 발췌(필요한 최소 범위) |
| `must_not_fire` | 이 룰이 발화하면 **오탐 재발** |
| `must_fire` | 이 룰이 사라지면 **미탐**(감쇄가 과해진 것) |
| `must_block` / `must_not_block` | 발화는 하되 차단 등급이 맞는가 |
| `was_blocked_before_fix` | 수정 전(`4466450`)에 실제로 차단이었는가 |

## 이 코퍼스가 유효하다는 근거

발췌가 너무 짧으면 원래 조건을 재현하지 못해, 테스트가 **통과하는 것처럼 보이지만
아무것도 지키지 않습니다**(라운드 12에서 실제로 겪은 실패입니다 — 파일 하나짜리
tmp 디렉터리 때문에 변이 검사가 통과했습니다).

그래서 10건 전부를 수정 직전 커밋 `4466450` 에서 돌려 **전부 차단으로 재현되는
것을 확인**한 뒤 등록했습니다. `was_blocked_before_fix: true` 가 그 사실입니다.

## 무엇을 보장하지 않나

- 저장소 **전체**를 덮지 않습니다. 판정이 뒤집힌 자리만 있습니다.
- 새로운 오탐 유형은 여기 없습니다 — 그건 실제 저장소를 다시 검사해야 나옵니다.
- 발췌라서 파일 전역 문맥(먼 곳의 import 등)에 의존하는 판정은 재현되지 않습니다.

즉 이것은 **회귀 방지**용이지 정확도 측정용이 아닙니다. 정확도는 여전히 남의
저장소를 실제로 검사해서 확인해야 합니다.

## 항목을 추가할 때

1. 원본 저장소·커밋을 고정하고 그 자리의 발췌를 넣습니다.
2. **수정 전 코드에서 실제로 재현되는지 확인**합니다. 재현되지 않으면 그 항목은
   아무것도 지키지 않습니다.
3. `why` 에 "왜 이 판정이 맞는가"를 사람 말로 적습니다. 6개월 뒤 이 줄만 보고도
   판단할 수 있어야 합니다.

## 인용 범위

각 항목은 판정을 재현하는 데 필요한 최소 줄만 담았습니다(대부분 1~7줄).
원본은 `origin` 의 저장소·커밋에서 확인할 수 있습니다.
