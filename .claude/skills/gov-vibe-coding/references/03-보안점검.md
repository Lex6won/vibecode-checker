# 3단계 · 보안점검 워크플로우 (MCP 전용)

목표: AI가 만든(또는 기존) 코드를 vibecode-checker / gov-vibe-security-kb **MCP 도구**로 점검하고,
공무원이 이해할 보고서와 수정 방향을 준다. (MCP 서버: GitHub `Lex6won/vibecode-checker`)

## 시작 전 1회

`server_status` 호출 → `rules_loaded_ok: true`, `total_rules`, `offline_mode` 확인.
- 연결 안 되면: 보안점검 불가를 알리고, MCP 설정 안내(아래 "MCP 미연결 시")로 넘어간다.
- `offline_mode: true`(망분리): 외부 저장소 URL clone 금지. **로컬 폴더 경로만** 점검.

## 점검 대상별 도구 선택

| 점검 대상 | 사용할 MCP 도구 |
|---|---|
| 메모리상의 코드 조각(방금 생성/붙여넣기) | `scan_code(code, filename, language)` |
| 로컬 파일·폴더 | `scan_path(path)` |
| 비밀값·개인정보만 빠르게 | `detect_secrets_and_pii(code)` |
| 의존성(requirements.txt / package.json) | `scan_dependencies(manifest_text, ecosystem)` |
| 특정 패키지 1개 안전성 | `check_package(name, ecosystem)` |
| 원격 저장소 URL | (온라인 한정) 먼저 `git clone --depth 1`로 임시 폴더에 받아 **읽기만** 하고 `scan_path`. 망분리면 거부. |

> 스캔 결과에서 의존성 매니페스트가 "검사 제외"로 표시되면 반드시 `scan_dependencies`로 별도 점검한다.

## 결과 정리 순서 (항상 이 순서)

1. **차단(decision=block) + 치명(critical)/높음(high)** — 저장·커밋·배포 전 반드시 고쳐야 함.
2. **자동 수정 가능(can_auto_fix=true)** — `suggest_fix(rule_id, unsafe_code)`로 안전 코드 예시 제시(미리보기만).
3. **나머지 경고(warn)** — 권고.

각 항목마다: ① 무슨 위험인지 **업무 영향**으로 1줄(예: "민원 DB가 통째로 조회·조작될 수 있음"),
② 결과의 `safe_fix` 또는 `suggest_fix`로 **고치는 법**, ③ 관련 룰 ID(근거).

## 보고서 만들기

`render_report(report, format="both")` → 한국어 Markdown + 인쇄용 HTML.
- 사람이 읽을 보고서면 `format="html"`, 기록·커밋용이면 `"markdown"`, 둘 다면 `"both"`.
- 결과를 `templates/보안점검결과.md`에 옮겨 최종 정리한다.

## 판정 해석 원칙 (오해 금지)

- **검사된 파일 0개 = 안전 아님.** 경로·확장자가 틀렸다는 신호 → 사용자에게 경로 확인 요청.
- **`requires_review`(판정 불가) = 안전 아님.** 사람이 직접 확인해야 한다는 뜻.
- critical/high는 기관 정책에 따라 **차단**. 이 도구는 공식 보안적합성 검토를 대체하지 않음 → 마지막에 기관 보안 담당자 확인 권고.

## MCP 미연결 시 안내

사용자에게 다음을 알린다(직접 실행하지 말고 안내만):
- MCP 서버 설치: `pip install git+https://github.com/Lex6won/vibecode-checker.git`
- Claude Code / Cursor의 MCP 설정(`.mcp.json`)에 vibecode-checker 서버 등록 필요.
- 망분리 환경은 `GVSKB_MODE=offline`, `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8` 환경변수 권장.
- 연결 전까지 기획·설계는 계속 가능, 보안점검만 보류.
