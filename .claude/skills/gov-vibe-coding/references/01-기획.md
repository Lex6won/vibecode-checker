# 1단계 · 기획 가이드

목표: 비전문가 공무원이 "막연한 아이디어"를 **1쪽짜리 기획서**로 만들도록 돕는다.
질문은 한 번에 하나씩, 쉬운 말로. 답을 들으면 정리해서 다시 확인한다.

## 꼭 물어볼 질문 (순서대로)

1. **무엇을 만들고 싶나요?** — 한 문장으로. (예: "민원인이 자주 묻는 질문에 자동 답하는 챗봇")
2. **누가 쓰나요?** — 일반 시민 / 내부 직원 / 특정 부서. (외부 공개 여부가 보안 강도를 좌우)
3. **어떤 데이터를 다루나요?** — ★가장 중요★. 이름·연락처·주민번호·민원내용·내부문서가 들어가는지.
   → 하나라도 해당하면 `references/데이터분류.md`로 등급을 매긴다.
4. **어디서 도나요?** — 인터넷(공개 클라우드) / 내부 행정망(망분리) / 개인 PC. (망분리면 외부 통신·외부 AI 금지)
5. **어떤 AI/외부 서비스를 쓰나요?** — 외부 LLM(ChatGPT 등) 호출 계획이 있는지. (있으면 개인정보 유출 위험 사전 경고)
6. **성공하면 어떤 모습인가요?** — 가장 중요한 기능 1~3개만. (욕심내지 않게)
7. **마감·제약이 있나요?** — 일정, 예산, 꼭 지켜야 할 기관 지침.

## 이 단계에서 미리 띄우는 보안 신호 (shift-left)

답변에서 아래가 감지되면, 코드를 짜기 전에 미리 알려준다:

- **주민번호·고유식별정보 언급** → "이건 고유식별정보라 평문 저장·외부 전송이 원칙적으로 금지입니다.
  설계 때 암호화·마스킹을 반드시 넣겠습니다." (관련 MCP 룰: `GOV-PII-RRN-001`, 판정 `block`)
- **외부 LLM에 업무 데이터 전송** → "공공기관은 원칙적으로 외부 AI에 업무 데이터 전송 금지입니다.
  개인정보 마스킹 게이트웨이나 기관 승인 모델만 쓰도록 설계하겠습니다." (룰: `GOV-LLM-PII-PROMPT-001`, `block`)
- **민원·결재·공문 데이터** → 내부정보로 분류, 접근통제·로그 설계 필요.
- **망분리 환경** → 외부 패키지·외부 API·외부 저장소 clone 불가. 오프라인 전제로 설계.

## 산출물

`templates/기획서.md`를 채운다. 핵심은:
- 한 줄 정의 / 사용자 / **데이터 등급(★)** / 운영 환경(망분리 여부) / 외부 AI 사용 여부 / 핵심 기능 / 제약.

## 마무리 멘트

"기획이 정리됐습니다. 여기서 정한 **데이터 등급과 운영 환경**이 다음 설계·보안 단계의 강도를 결정합니다.
이제 어떻게 만들지(설계)로 넘어갈까요?"
