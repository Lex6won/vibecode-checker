# 2단계 · 설계 가이드

목표: 1단계 기획을 **비전문가가 감당할 수 있는 단순한 구조**로 옮기고,
**보안 결정을 코드 작성 전에 미리 못 박는다.**

## 설계 원칙 (비전문가 우선)

1. **가장 단순한 구조부터.** 기능 1~3개면 단일 앱(예: 파이썬 + 간단한 웹 프레임워크)로 충분하다. 마이크로서비스·쿠버네티스 같은 과한 구조 금지.
2. **익숙하고 안전한 기술 스택 추천.** 사용자가 모르면 합리적 기본값을 정해주고 이유를 한 줄로 설명한다.
3. **데이터 흐름을 그림처럼 글로 적는다.** "입력 → 처리 → 저장 → 출력" 각 칸에서 개인정보가 어디를 지나는지 표시.
4. **외부로 나가는 지점(egress)을 명시한다.** 외부 API·외부 LLM·외부 패키지 설치 — 망분리면 전부 차단 대상.

## 보안을 설계에 미리 심기 (핵심)

1단계에서 분류한 **데이터 등급 + 운영 환경**에 따라 아래를 설계서에 *결정사항*으로 적는다.

| 기획에서 나온 것 | 설계에 미리 박는 보안 결정 |
|---|---|
| API 키·비밀번호 사용 | 코드에 하드코딩 금지 → **환경변수/시크릿 매니저**에서 로드 |
| 주민번호·고유식별정보 | 평문 저장 금지 → **암호화 저장**, 화면·로그엔 **마스킹**, 테스트는 더미데이터 |
| 외부 LLM 호출 | 개인정보 **마스킹 게이트웨이** 통과 또는 기관 승인 모델만, 프롬프트 로깅 시 PII 제거 |
| 사용자 입력 → DB 조회 | 문자열 이어붙이기 금지 → **파라미터라이즈드 쿼리**(SQL 인젝션 방지) |
| 사용자 입력 → 화면 출력 | 그대로 출력 금지 → **이스케이프/템플릿 자동 escape**(XSS 방지) |
| 외부 패키지 사용 | 설치 전 **`check_package`로 안전성 확인**, 오타스쿼팅(이름 유사 악성패키지) 주의 |
| 망분리 운영 | 외부 통신·외부 패키지·외부 저장소 clone **전면 금지**, 내부 미러만 사용 |

## MCP로 관련 룰 미리 찾기 (선택이지만 권장)

설계 시나리오를 정하고, 해당 시나리오의 보안 룰을 미리 본다. 검색은 **짧은 단일 키워드**가 잘 맞는다(긴 문장은 0건 날 수 있음).

- 시나리오 태그: `web-app`, `llm-integration`, `rag`, `agent`, `data-pipeline`
- 예: `search_rules(query="개인정보", scenario="llm-integration")`,
  `search_rules(query="SQL", language="python")`, `search_rules(query="입력검증")`
- 마음에 걸리는 룰은 `get_rule(rule_id=...)`로 "안전한 패턴" 본문을 읽고, 그 패턴을 설계서에 반영한다.

이렇게 하면 AI가 코드를 만들 때 처음부터 안전한 패턴을 쓰게 되어, 3단계 보안점검에서 걸리는 게 줄어든다.

## 산출물

`templates/설계서.md`를 채운다: 기술 스택 / 단순 구조도(글) / 데이터 흐름 / **보안 결정사항 표** / 외부 egress 목록.
