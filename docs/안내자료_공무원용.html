01왜 필요한가

“AI한테 시켜 만든 코드, 그냥 써도 되나요?”

ChatGPT·Claude·Copilot·Cursor로 빠르게 만든 코드에는 눈에 안 보이는 보안 위험이 숨어 있습니다. 하지만 공무원 대부분은 보안 전문가가 아닙니다.

개인정보

주민번호·전화 평문 저장

암호화·마스킹 없이 파일/DB에 그대로 — 유출 시 통지·과징금

비밀값

API 키·비밀번호 코드에 박힘

저장소·로그로 새면 계정·시스템·클라우드 탈취

원격 실행

SQL 삽입 · 명령 실행

민원 DB 전수 유출, 서버 원격 장악으로 직결

공급망

취약·가짜 패키지

알려진 CVE, 오타 노린 가짜 라이브러리 설치

💡 실제로 운영서버에 올리기 전 이런 위험을 걸러낼 쉬운 1차 점검 도구가 필요합니다.

03어떻게 쓰나 — 사용법

둘 중 편한 방법으로

방법 A · 쉬움

AI 코딩 도구에 그냥 말하기

VS Code·Cursor·Claude 등에 한 번 연결(MCP)해 두면:

“이 폴더 보안 검사 해줘”
 
“보안 점검 리포트 써줘”

트리거: 보안·점검·체크·검토·검사·스캔·“안전한지”

방법 B · 터미널

명령 한 줄

gvskb scan ./내프로젝트 -o 보안점검.md

결과를 .md + .html로 저장 → 인쇄하면 그대로 PDF 결재 문서.

패키지까지 함께: --check-deps

06결과에 어떻게 대응하나 — 절차

“배포 미승인”이 나오면 — 3단계

1

고치기

쓰던 AI 도구에 그대로 말하세요.

“나온 위험들 안전하게 고쳐줘”
2

확인하기

AI가 바꾼 내용을 살펴보고 적용. 업무 로직이 바뀌면 담당자와 상의.

3

다시 검사

고친 뒤 재검사해 0건이 되는지 확인.

“다시 검사해줘”
발견 유형이렇게 대응하세요
API 키·비밀번호코드에서 지우는 것만으론 부족 → 반드시 새로 발급(폐기), 유출 의심 시 보안담당자 통지
개인정보 평문암호화·마스킹 후 저장, 수집 자체 재검토 → 유출 정황 시 개인정보보호 담당자에게 통지
SQL·명령 삽입문자열 조합 대신 파라미터 바인딩, shell=True/os.system 회피
취약 패키지안전한 버전으로 업그레이드/교체 (판정 불가는 ‘안전’ 아님 — 재검사)
⚠ 치명·높음 항목은 기관 정책에 따라 보안담당자 검토를 거쳐야 하며, 본 도구는 공식 보안성 검토를 대체하지 않습니다.

08도입 & 요약

지금 바로, 안전하게 시작

① 설치

Python 3.11+ · GitHub 소스 설치. 망분리는 외부망에서 받아 반입.

② 연결

AI 도구(MCP) 한 번 연결하거나 터미널에서 바로 사용.

③ 검사·대응

배포 전 검사 → 결론 확인 → 3단계 조치 → 보안팀 제출.

  • 소스는 밖으로 안 나갑니다 — 로컬 정적분석, 망분리 지원
  • 비전문가도 이해 — 위험·이유·수정법·근거를 한국어로
  • 공식 검토를 대체하지 않는 1차 보안 게이트 — 치명·높음은 보안담당자 검토
