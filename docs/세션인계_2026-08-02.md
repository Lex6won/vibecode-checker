## 3. gg-trusted-registry 연동 — 설계 협상 종료, 구현 단계

**세 시스템 전체 그림: `docs/3자구조_체커-레지스트리-하네스.md`** ← 여기부터 읽을 것
**체커↔레지스트리 계약: `docs/연동합의_gg-trusted-registry.md`**
**집행 계약: `docs/하네스_집행계약.md`**
관계 정의·경계·API 계약·결정 연혁이 전부 여기 있습니다. 라운드별 문서 6종은 근거
기록이며, 충돌 시 합의서가 우선합니다.

핵심만:

1. **의존은 단방향** — 레지스트리가 없어도·죽어도 gvskb는 온전히 동작. 환경변수 옵트인
2. **관측과 판정을 섞지 않음** — gvskb는 승인 권한 없음, 레지스트리는 코드 안 봄
3. **fail-open, 침묵 금지** — 조회 실패가 검사를 막지 않되 반드시 표시
4. **로컬 탐지가 최종 안전망** — 기관 승인도 로컬 악성·KEV 대조를 건너뛰지 못함
5. **알림 단위는 조치 단위를 따름** — 시스템 열화는 배너 1개, 패키지 판정만 패키지별로

**하네스 집행계약**(`docs/하네스_집행계약.md`)이 합의서 §10 으로 편입됐습니다.
두 시스템이 판정을 만들고 저장하지만 **실제로 설치를 막는 곳**이 계약에 없다는
지적을 레지스트리가 R7 에서 제기했고, 그 자리를 채운 문서입니다.

### 3-1. 세 시스템 호출 방향 (가장 중요)

```
하네스 ──판정 요청──▶ gvskb ──조회──▶ 레지스트리
       ◀──판정 결과──       ◀──판정──
                        └──제출(관측)──▶
```

**하네스는 레지스트리를 직접 조회하지 않습니다.** 직결하면 로컬 악성·KEV 대조를
건너뛸 수 있고(원칙 4 위반), fail-open 로직이 두 곳으로 갈라지며, API 키 유출면이
두 배가 됩니다. **하네스 쪽에서 직결을 설계 중이라면 지금 맞춰야 합니다.**

### 3-2. 하네스 운영 정책 — 4/5 확정 (2026-08-02 기관 결정)

| 항목 | 결정 |
|---|---|
| 시작 모드 | **MONITOR** |
| MONITOR → WARN | 2주 운영 후 |
| WARN → ENFORCE | **직접 의존성의 `unknown` 비율 10% 이하가 3주 연속** |
| `unknown` 차단 범위 | **직접 의존성에만**(전이 의존성은 절대 규칙만 적용) |
| 카탈로그 | allow·deny 둘 다 존재 → 집행계약 §6-3 평가 순서 |
| **우회 정책** | **미정 — 3자 합의 대기**(집행계약 §10 에 제안) |

`unknown` 차단을 전이 의존성까지 적용하면 **ENFORCE 에 영원히 도달할 수 없습니다** —
락파일 하나에 수백~수천 건인데 그걸 다 등록하려면 심사 큐가 감당 못 하고,
이는 §5-C("락파일은 큐에 안 올림")와 정면으로 어긋납니다.

연동을 막는 기술 항목은 없습니다. 남은 것은 §4 의 외부 회신 대기입니다.

게이트를 통과시키지 못합니다.** 지금은 PAT로 PR을 만들어 정상 경로를 탑니다.
이 교훈은 `tests/test_workflows.py`에 가드로 고정돼 있습니다.

## 8. 작업 원칙 (계속 유지)

1. **도구의 주장을 그대로 옮기지 않는다** — 원본 소스에서 확인한 것만 판정으로 기록.
   상대 저장소처럼 접근할 수 없는 곳의 보고는 "그쪽 보고"로 표기한다.
2. **우리 도구의 오탐도 상용 도구와 같은 기준으로 기록한다.**
3. **과잉 교정을 경계한다** — 문맥 분류가 구체적 경고를 덮어쓴 결함(`1d3d119`)이 실례.
4. **실패는 올바른 곳에서 나게 한다** — 조용한 초록불이 빨간불보다 위험하다.
5. **커밋·푸시는 명시적으로 요청할 때만.**
6. **경고 피로는 탐지력 저하다** — 같은 사유로 수백 줄이 뜨면 담당자는 무시하게 되고,
   그러면 그 사이의 진짜 위험도 함께 묻힌다. 조치 단위가 다르면 알림 단위도 다르게.

### 이번 세션에서 얻은 것

- **변이 검사**: 새로 만든 가드가 실제로 실패하는지 확인한다. 세 번 썼고 세 번 다
  유효했다. 실패하지 않는 테스트는 초록불을 하나 더 만들 뿐이다.
- **커밋 전 파일에 `git checkout`을 쓰지 않는다** — 변이 검사 되돌리다 미커밋 작업을
  날린 적 있음. 백업 사본을 쓸 것.
- **시크릿을 예시에 쓸 때 실제 벤더 접두사를 피한다** — `sk_live_`를 룰 예시에 넣었다가
  GitHub 푸시 보호에 막혔다. 우회 URL은 쓰지 않고 가상 접두사로 바꿨다.
- **기록은 뒤처지기 쉽다** — 커밋 메시지는 남기면서 CHANGELOG·합의서 연혁·인계
  문서를 며칠 방치했다. 작업이 끝날 때가 아니라 **커밋할 때 같이** 갱신할 것.
- **문서에 '알려주시면 확정하겠습니다'를 남기지 않는다** — 하네스 카탈로그 형식을
  모른다는 이유로 §6 을 미완성으로 두었다. 모르면 **경우를 나눠 전부 명세**하면 된다.
  상대에게 숙제를 넘기는 문장은 그 문서를 못 쓰게 만든다.
- **주석에만 있는 안전장치는 안전장치가 아니다** — `_kev_cve_hits` 주석이
  "'악용 없음'이 아니라 '대조 못 함'"이라고 정확히 적어 뒀지만 그 구분이 반환값에
  없어 아무도 알 수 없었다.
