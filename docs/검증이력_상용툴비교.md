### 3.3 라운드 2에서 새로 발견 — BOM 결함 (자체 발견)

**증상**: BOM(`U+FEFF`)으로 시작하는 Python 파일은 **AST 분석이 통째로 건너뛰어짐**.

```
app.py           → BOM 있음 → ast.parse 실패(invalid non-printable character U+FEFF)
app_20260607.py  → BOM 있음 → 동일
결과: AST 정밀 판정(SQL 테인트·무한루프)이 적용되지 않고 regex로만 검사됨
```

- 원인: `scanner.py`가 `encoding="utf-8"`로 읽어 BOM이 문자로 남음 (`utf-8-sig`면 정상 파싱)
- 영향 범위: **Windows·한글 환경에서 매우 흔함**. 이 프로젝트의 가장 큰 두 파일(138KB·136KB)이 해당
- 결과: §2.4의 남은 critical 2건이 바로 이 때문. 즉 **P0 수정이 정작 대상 파일에 적용되지 않았음**
- 예상 수정: `read_text(encoding="utf-8-sig")` 1줄 + 회귀 테스트

> 이 결함은 "조용한 성능 저하"라 가장 위험한 유형입니다. 도구는 정상 동작한 것처럼 보이지만 정밀 엔진이 꺼집니다.
