# 46차 — 패키지 검사 기본 실행 · 위협정보 신선도 게이트 · 번들 전자서명 (2026-11-02)

## 1. 결정

패키지(의존성) 검사가 `--check-deps` 옵션일 때만 돌아가던 구조를 바꾼다. 바이브코딩 앱의 실제 위험은 직접 쓴
코드보다 가져다 쓴 패키지에 있고, 실제 악용이 확인된 취약점·악성 패키지는 소스 룰로는 잡히지 않는다. 옵션을 모르는
공무원이 옵션 없이 "승인"을 받는 결과는 이 도구가 가장 경계하는 조용한 초록불이었다.

**세 층으로 나눈다.** 옵션 하나가 로컬 대조와 외부 조회를 한 덩어리로 켜고 껐기 때문에 기본값 논쟁이 생겼다.

| 층 | 하는 일 | 네트워크 | 기본 |
|---|---|---|---|
| 1 로컬 대조 | 매니페스트·락파일을 로컬 위협정보 캐시(OSV 취약점·악성, CISA KEV, EPSS, NVD, KNVD)와 대조 | 없음 | 항상 |
| 2 신선도 판정 | 캐시 없음 → 판정 불가(종료코드 3) · 오래됨 → 조건부(1) · 보고서가 조치를 말함 | 없음 | 항상 |
| 3 온라인 조회 | 공식 저장소 실재·발행일·쿨다운, OSV 실시간 (패키지명·버전 전송) | 있음 | `--deps online` |

번들 **내려받기**(autopull)는 3층이 아니라 1층의 전제다 — 보내는 것이 없으므로 로컬 모드에서도 켠다. 망분리
(`GVSKB_MODE=offline`)와 옵트아웃(`GVSKB_AUTO_UPDATE=off`)은 그대로 존중한다.

## 2. 앞서 미결이던 3건의 답

1. **캐시 없음을 판정 불가로 올릴지** → 올린다. 매니페스트가 없는 프로젝트(정적 페이지)는 영향 없음. 처음 설치한 PC
   의 첫 검사는 종료코드 3 이 될 수 있으므로 안내 문구가 "위협정보를 받으라"로 명확해야 한다(보고서 배너·터미널 동일 문구).
2. **오래됨 기준일** → 기존 `GVSKB_INTEL_MAX_AGE_DAYS`(기본 2일) 하나로 간다. 폐쇄망 기관은 반입 주기에 맞춰 설정한다.
   환경등급(E0~E2) 연동은 쿨다운 의미와 섞여 보류.
3. **기본값 전환의 영향** → CHANGELOG 에 "판정 기준이 바뀐다"를 명시. 지금까지 옵션 없이 승인받던 프로젝트가
   조건부·차단·판정 불가로 바뀔 수 있고, 그것이 의도다.

## 3. 바뀐 것 (코드)

- `src/gvskb/deps_check.py` 신설 — 모드 결정(`resolve_deps_mode`), 위협정보 상태(`intel_state`), 매니페스트 수집, 감사 실행
  (CLI·MCP 공용 본문), 결과 기록(`attach_dependency_check`), 터미널 문구(`user_notice`).
- `cli.py` — `--deps {local,online,off}` 신설(기본 local, 기관 기본값 `GVSKB_DEPS_MODE`), `--check-deps` 는 online 별칭.
  재현 명령은 기본과 다를 때만 `--deps X` 를 적는다. `intel-bundle` 에 `verify`·`keygen` 동작과 `--sign-key-env`·`--key-id` 추가.
- `server.py` — MCP `scan_path` 가 같은 코드·같은 기본값으로 패키지 검사를 수행(`deps`, `env_grade` 인자). 예전에는 의존성을
  전혀 보지 않았다(가장 큰 구멍). 동기 도구가 이벤트 루프 안에서 불려도 되도록 래퍼가 별도 스레드 루프를 쓴다.
- `tools/check_package.py` — `mode` 인자. 로컬 모드는 오프라인 캐시 대조 경로를 재사용하되 사람에게 보이는 말을
  "오프라인"이 아니라 "로컬 위협정보"로 적는다. 결과에 `check_mode`.
- `gate.py` — `intel_gap`("" | stale | missing). stale → `intel_stale` 조건부, missing → undetermined. 이유 문장 추가.
- `report.py` — 머리표 「판정 기준」에 "위협정보 MM.DD HH:MM 수집"(없음/생략도 표기), 상태별 배너 한 줄(md·html).
  옛 "의존성 검사 별도 필요" 배너는 기록 없는 구버전 JSON 에서만.
- `schema.py` — `ScanReport.dependency_check`, `PackageCheckResult.check_mode`.
- `diagnostics.py` — 캐시 없음은 모드 무관 WARN(osv-vulns 포함 3종), 서명 정책 줄.
- `intel/signing.py` 신설 — Ed25519(RFC 8032 §6 참조 구현, 순수 파이썬). `TRUSTED_PUBLIC_KEYS`, `GVSKB_INTEL_TRUSTED_KEYS`,
  `GVSKB_INTEL_REQUIRE_SIGNATURE`. `intel/bundle.py` — export 서명(`manifest.sig`), import 검증(서명 → manifest → 파일 해시),
  `verify_bundle`(쓰지 않고 검증).
- `.github/workflows/update-intel.yml` — Secrets `GVSKB_INTEL_SIGNING_KEY` 가 있으면 서명해 게시, 없으면 경고.
- 테스트 — `test_round46_deps_default.py`(19) · `test_round46_bundle_signing.py`(13). `conftest.py` 가 모든 테스트에
  빈 캐시 폴더·자동 갱신 꺼짐을 기본으로 고정(개발 PC 의 실제 캐시가 판정을 흔들지 않게).

## 4. 사용자 문구 (확정)

| 상태 | 머리표 | 배너 / 터미널 |
|---|---|---|
| 정상 | `위협정보 11.02 03:17 수집` | 없음 |
| 오래됨 | `위협정보 … 수집 ⚠ 9일 경과` | ⚠ 위협정보가 9일 전 것입니다 — 그 사이 새로 알려진 취약점은 반영되지 않았습니다. 패키지 판정은 '조건부'. 조치: (인터넷망) `gvskb update-intel` 후 재검사 · (폐쇄망) 전산 담당자에게 갱신 요청 |
| 없음 | `위협정보 없음` | ⛔ 패키지 검사를 하지 못했습니다 — 위협정보가 이 PC에 없습니다. … 이 결과를 '통과'로 쓰지 마세요. 조치: (인터넷망) `gvskb update-intel` · (폐쇄망) 관리자가 배포한 위협정보 폴더를 `GVSKB_INTEL_DIR` 로 지정 |
| 생략 | `패키지 검사 생략` | ℹ 패키지 검사를 생략했습니다(`--deps off`) — 패키지 취약점은 이 보고서에 없습니다 |

CVE 번호·EPSS·CVSS 는 본문이 아니라 부록·JSON 에만 둔다. 취약 패키지 행은 기존대로 "**X 이상**으로 올린 뒤 다시 검사하세요".

## 5. 운영 절차 — 서명 키 (관리자, 처음 한 번)

```bash
gvskb intel-bundle keygen --out intel-signing.key        # 비밀키 파일(0600) + 공개키 hex 출력
```

1. 비밀키 파일 내용을 GitHub 저장소 Settings → Secrets `GVSKB_INTEL_SIGNING_KEY` 로, key_id 를 Variables `GVSKB_INTEL_KEY_ID` 로 등록.
   파일 원본은 오프라인 보관(저장소에 절대 넣지 않는다).
2. 공개키를 `src/gvskb/intel/signing.py` 의 `TRUSTED_PUBLIC_KEYS` 에 key_id 와 함께 추가해 **먼저 배포**한다.
   순서가 거꾸로면(Secrets 만 먼저) 갱신 워크플로의 반입 재검증이 "신뢰 목록에 없는 키"로 막힌다 — 의도된 안전장치.
3. 공개키가 깔린 뒤 기관 PC 에 `GVSKB_INTEL_REQUIRE_SIGNATURE=1` 을 켜면 서명 없는 번들은 거부된다.
4. 키가 새면 새 쌍을 추가 배포하고 교체 기간 뒤 옛 키를 지운다(여러 키 동시 허용).

공식 인증서(GPKI 등)는 쓰지 않는다 — 검증하는 쪽이 체커 자신이고 공개키가 체커와 함께 배포되므로 제3자 증명이 필요
없다. 검증이 순수 파이썬이라 폐쇄망 설치본에 새 의존성이 없다.

## 6. 폐쇄망 자동 반입 (권장 구조)

인터넷망 수신 서버(`gvskb intel-sync` 예약 작업) → 망연계 일방향 전송(zip 1개) → 업무망 공유 폴더(`GVSKB_INTEL_DIR`)
또는 사내 URL(`GVSKB_INTEL_URL`) → 각 PC 자동 반입. 수신 서버는 배포 전 `gvskb intel-bundle verify` 로 서명·해시를
확인한다. **서명이 들어간 뒤에 켠다.**

| 지적 | 반영 |

| M-3 실패 후 24h 스로틀 | 실패 뒤 1시간 재시도, 자동 갱신 결과를 `dependency_check.auto_refresh` 에 기록·안내문 포함 |
| M-4/5 예제 | pre-commit `--deps off --fail-on block`, GitHub Actions `gate.verdict` 판정 + `intel-sync` |
| M-6/7 멤버 크기 상한·원자적 기록 | sig 64KB·manifest 8MB·폴더 번들 300MB 상한, tmp+`os.replace` |
| LOW | 배너 중복 축소(조치만), 비문 수정, local 모드 "오프라인" 표현·`offline` 플래그 정리, doctor 종료코드 변화 CHANGELOG 명시 |

**남은 성능 과제.** osv-malicious 53MB·osv-vulns 34MB 를 매 프로세스 파싱한다. 패키지명 기준 인덱스 사이드카를 만들어
필요한 항목만 읽으면 1초 아래로 내릴 수 있다. 0.6.x 에서.
