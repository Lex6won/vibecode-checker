## 1. 산출물 흐름

```
[체커 gvskb scan]
   ├─ 점검 리포트  <stem>.html / .json  ── 「서식 대응」 절(A4) 포함 ──▶ 포털: [붙임] AI체커 결과
   ├─ SBOM 원본    <stem>.sbom.cdx.json (CycloneDX 1.6, A1)         ──▶ 포털: [붙임] SBOM (JSON)
   └─ SBOM 보고서  <stem>.sbom.html  (결과보고서·패키지 목록·의존관계, A2·A3) ──▶ 포털: [붙임] SBOM (HTML)
[스패로우] 별도 점검 ─────────────────────────────────────────────────▶ 포털: [붙임] 업로드
[포털] 서식 작성 화면(사람 입력 + 체커 자동 채움) → 전자서약(이메일 본인 확인) → 검토요청 → 서식 hwpx + 붙임 묶음
```

- HTML 보고서를 **체커가 만든다**: 같은 화면이 포털·하네스·망분리 PC 어디서나 똑같이 보이고, 포털은 파일만 제공하면 된다.
- 리포트 JSON 에 `form_v12`(A4)·`sbom_verification`(A2) 블록을 넣어 포털이 서식 칸을 자동으로 채운다.

## 2. 체커 작업 (A) — 서식 붙임 2종을 만든다

## 3. 포털 작업 (B) — 서식을 표현하고 서약을 받는다

| ID | 작업 | 현재(코드 확인) | 설계 |
|---|---|---|---|
| **B1** | 붙임 제공 | 리포트·SBOM 원본(`.sbom.cdx.json`)은 점검 결과에 있음 | SBOM **HTML 보기 + JSON 내려받기** 두 개, 체커 리포트 첨부, **스패로우 결과 업로드 칸**(PDF·HTML, 크기 제한·형식 검사) |
| **B2** | 서식 작성 화면 + hwpx 출력 | hwpx 템플릿·검증 스크립트 있음 | 사람 입력(사업개요·담당자·운영망·프로그램 형태·실행권한·처리정보 등급·개인정보·개발과정 외부전송) + 자동 채움(언어 버전·외부 연계 4분류·8항목 결과·SBOM 8행). 자동 값은 「체커 산출」 표시, 사람이 고치면 이력. 「확인 안 된 것을 '없음'으로 바꾸지 않는다」(작성방안 문서 원칙). 출력 = v1.2 서식 hwpx |
| **B3** | **메일 발송(본인 확인)** | `PORTAL_AUTH_PROVIDER=smtp` 는 설정값으로만 있고 발송 코드 없음. 로그인 링크는 개발 모드에서만 화면에 표시 | **의존성 없는 내장 SMTP 클라이언트**(Node `net`/`tls`, STARTTLS·SMTPS·AUTH PLAIN/LOGIN, 시간 제한, 재시도 1회, 감사 기록). 설정: `PORTAL_SMTP_HOST`·`PORT`·`SECURITY=starttls|smtps|none`·`USER`·`PASSWORD_FILE`(비밀번호는 파일로)·`FROM`·`TLS_CA_FILE`(기관 사설 인증서). `smtp` 모드에서 설정이 빠지면 **기동 거부**. `gvskb`처럼 `node scripts/smtp-check.mjs` 로 연결 시험. 테스트는 로컬 가짜 SMTP 서버로 |
| **B4** | **전자서약** | 없음 | 서약 본문 = v1.2 원문(버전 ID·본문 sha256 고정). 동의 시 저장: 이메일(본인 확인된 계정)·소속·성명·서약 버전·본문 해시·시각·IP·인증 방식, **해시 체인 감사 기록**(관리자 위변조 방지). 유효한 서약이 있어야 검토요청 가능. 본인 확인 = 메일 링크(B3) 또는 Cloudflare Access 이메일 인증 |
| **B5** | 판정 표시 규칙 | — | 내부망 + AI 서비스 연계 → 부적합, 개발과정 외부전송 「있음」 → 부적합, 8항목 결과는 체커 값 그대로 |
| **B6** | 보안담당자 역할·승인 기록 | 관리자 1계정 | 역할 분리(보안담당자만 승인), 승인 시 해시 기록(다음 ZONE 상승 근거) |
| **B7** | 하네스 영수증 첨부 | — | 서식 5항 「하네스 가능여부판단」 근거로 영수증 업로드·검증 |
